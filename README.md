# SheetDiff 📊

**自动找出两个数据源之间的差异规律，减少确认成本。**

## 这个工具解决什么问题？

假设这样一个场景：

你们系统需要和另一个平台保持数据一致。数据同步跑完了，一比对——发现两边对不上。你的系统里多了一些记录，对方的系统里也多了一些记录，没人说得清为什么。

去找对方的技术对接人问，要么这个人已经不在了，要么他也很茫然，要么为了一条数据差异要来回沟通好几天。

SheetDiff 就是为了这个场景设计的。

## 它怎么帮你？

把两边导出的数据放到同一个 Excel 文件里，用 SheetDiff 跑一遍，它会自动分析：**"你的数据里多出来的那些记录，有什么共同特征？"**

比如它能告诉你：
- 数据源A 多出来的记录，全都是 `部门 = 技术部` 的人
- 数据源B 多出来的记录，全都是 `状态 = 已离职` 的人

有了这些规律，你不需要逐条核对，也不需要反复找人确认。看一眼结果就知道问题出在哪，直接针对性解决。

## 核心概念：什么是"独有"？

这是理解输出结果最关键的概念。

### 直观理解

你的系统导出了一份数据（数据源A），对方的系统导出了一份数据（数据源B），用主键匹配后发现：

- **80 条记录两边都有**（匹配上了，没问题）
- **20 条只在你的系统里有**（A 有 B 没有——**A 独有**）
- **10 条只在对方的系统里有**（B 有 A 没有——**B 独有**）

SheetDiff 要回答的问题就是：**这 20 条和 10 条"独有"记录，有什么规律？**

### 用集合论理解

```
数据源A 主键值集合 = {1, 2, 3, ..., 100}                    ← 100条
数据源B 主键值集合 = {1, 2, ..., 80, 101, 102, ..., 110}   ← 90条
                          ↑前80个重叠      ↑后10个是独有的

匹配行（主键值在两边都存在）= {1, 2, ..., 80}                ← 80条
A 独有行（主键值仅在 A）   = {81, 82, ..., 100}             ← 20条
B 独有行（主键值仅在 B）   = {101, 102, ..., 110}           ← 10条
```

### 输出结果怎么读？

假设发现：
- A 的所有独有行都是 `部门 = 技术部` → 对方平台缺少技术部的人员数据
- B 的所有独有行都是 `状态 = 已离职` → 你们的系统没有及时清理离职人员

一次运行，结论直接摆出来，不需要猜。

### D 集合（误伤独有行数）

这是算法中最重要的衡量指标。假如：

- 某字段规律 `部门 = 技术部` **覆盖了全部 80 条匹配行**
- 但在 **20 条 A 独有行**中，有 **3 条不是技术部的**
- 那么 D = 3，误伤率 = 3/20 = 15%

**D = 0** 表示完美规律，不会误伤任何独有行，这就是最优解。

> **一句话总结**：独有 = 两边的数据匹配不上的记录。"独有行"就是差异本身，D 值度量的是一个规律在解释差异时"误伤"了多少本不该被包含的记录。

## 工作原理

把数据源A和B放在同一个 Excel 文件的两个 Sheet 中，配置好主键映射，SheetDiff 执行以下流程：

1. **读取配置** — 从专用配置 Sheet 读取字段映射、主键定义
2. **主键匹配** — 根据主键做行匹配，产生三个集合：**匹配行**、**A 独有行**、**B 独有行**
3. **逐字段分析** — 对每个非主键字段，自动发现能覆盖**全部**匹配行的过滤模式，同时最小化对独有行的误伤
4. **构建支配关系森林** — 将发现的规律组织成层次结构，最优规律支配次优规律
5. **推荐最优组合** — 自动找出能解释全部差异的最佳过滤条件组合

## 功能特性

- **5 种规律类型**（每字段自动检测）：
  - `等于` — `部门 = 技术部`
  - `枚举` — `部门 ∈ {技术部, 市场部}`
  - `前缀匹配` — `编码 = A*`
  - `前缀枚举` — `编码 ∈ {A*, B*}`
  - `数值范围` — `年龄 >= 32`
- **复合主键**支持（多个字段联合作为主键）
- **支配关系森林**可视化 — 直观展示条件之间的优劣关系
- **最优组合推荐** — 自动发现误伤为零的最佳过滤条件组合
- **直接输出到 Excel** — 在原文件中生成分析结果 Sheet，带颜色高亮
- **重复列名检测** — 发现重复列名时快速失败，避免歧义
- **零外部依赖** — 直接操作 `.xlsx` 文件，无需数据库

## 使用方法

```
SheetDiff.exe <文件.xlsx>
```

或者将 `.xlsx` 文件拖拽到程序图标上。如果不指定文件，程序会自动查找当前目录中的 `.xlsx` 文件。

### Excel 配置

你的 Excel 文件中需要包含一个名为 **"配置"** 的 Sheet，结构如下：

| 键 | 值 |
|-----|-------|
| 数据源A Sheet名 | A数据所在的Sheet名称 |
| 数据源B Sheet名 | B数据所在的Sheet名称 |
| 数据源A 表头行 | 1 |
| 数据源B 表头行 | 1 |

*（空行 — 分区标记，分隔基础配置和字段映射）*

| 数据源A字段 | 数据源B字段 | 是否主键 |
|------------|------------|---------|
| id | id | 是 |
| name | name | |
| department | dept | |

默认值：数据源A Sheet 名 = `"主表"`，数据源B Sheet 名 = `"参考表"`，表头行号 = 1。

> **注意**：配置中的"主表"和"参考表"是历史命名，对应数据源A和数据源B。两者地位对等，没有主次或新旧之分。

## 输出说明

SheetDiff 会在你的 Excel 文件中新增一个 **"分析结果"** Sheet，包含以下内容：

1. **统计概览** — 行数、匹配率
2. **推荐过滤条件组合** — 能完全解释独有行的最佳条件组合
3. **支配关系森林** — 条件之间关系的树形展示（绿色 = 完美，误伤为零）
4. **过滤条件链详情** — 每个字段发现的所有规律及其误伤指标
5. **数据样本** — 匹配行、A独有行、B独有行的示例数据
6. **主键高亮** — 源 Sheet 中匹配成功的主键单元格标记为绿色背景

## 算法原理

核心是基于集合论的：

- 对每个非主键字段，生成候选模式（等于、枚举、前缀、范围）
- 每个模式定义一个 **D 集合** — 即该规律会错误纳入的独有行集合（误伤）
- 构建**支配关系森林**：若模式 A 的 D 集合 ⊆ 模式 B 的 D 集合，则 A 支配 B
- 搜索 **D 集合互不相交**的模式组合，实现总误伤为零的最优解

详见 [ALGORITHM_DESIGN.md](ALGORITHM_DESIGN.md)。
